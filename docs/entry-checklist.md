# Before you submit

[English guide](../README.md) · [Panduan Indonesia](mulai-di-sini.md)

Use this as a review sheet with your agent. The selected bounty's current requirements take priority; not every item applies to every entry format.

## Choose the right account and task

- [ ] The agent verified the connected make.fun handle against yours.
- [ ] The task is open, and you know its entry deadline in your time zone.
- [ ] You checked the entry fee and any other paid prerequisites against your budget.
- [ ] You know the actual ranking metric and which places receive money.
- [ ] The required applications, runtime and linked accounts are available.

## Preserve a build record that can qualify

- [ ] The build-session timing matches the competition's opening rules.
- [ ] If a live recording is required, it started before the build session.
- [ ] The harness saved genuine session logs; none were reconstructed or altered to pass.
- [ ] The agent genuinely tested or inspected the result and revised it.
- [ ] The kit's authorship, turn-count and revision checks pass.
- [ ] The run record and instruction context are complete; unneeded personal details are redacted using the kit's supported options.

## Check the work you will actually send

- [ ] The program, page, game or guide works when opened or run as the rules specify.
- [ ] The required files are present at the exact paths and capitalization requested.
- [ ] Any screenshots come from the real output, not a mockup presented as evidence.
- [ ] The license, README badges and repository About satisfy this bounty's checks.
- [ ] Wallet files, credentials and private transcript bundles are outside the public repository.
- [ ] You ran the local grader if one is provided, plus the kit's pre-submit checks.

## For a public GitHub entry

- [ ] The repository was created after opening, if the bounty requires it.
- [ ] Its owner meets the exact ownership rule. A claim file is not valid for every bounty.
- [ ] The full submitted commit is pushed to a branch and matches the checked files.
- [ ] You will keep it public and preserve any default-branch content needed for the final re-check.

## After submitting

- [ ] You saved the submission ID and receipt.
- [ ] You read the authenticated server status after snapshot and transcript processing.
- [ ] A failure is fixed according to its specific reason before another attempt.
- [ ] You follow the server's wait advice if processing is delayed.
- [ ] You distinguish a provisional rank from a final paid place.
- [ ] Before any resubmission, you checked how the competition handles the latest entry and tie-breaks.

A good final report names the entry, commit, tests, server status, any remaining failure and the next action. "The upload succeeded" alone is not enough.

## When a prize appears

- [ ] The account actually shows a claimable prize, with amount and claim deadline.
- [ ] You can access the wallet entitled to the payout.
- [ ] You inspected any network fee or quoted deduction before approving a claim.
- [ ] You verified the resulting payment instead of assuming a claim request paid it.
